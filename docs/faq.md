## 📌 基础问题

### Q1: 文匠 (Wenjiang) 是什么？
**A:** 文匠是一款专为解决 **Markdown 转换 Word (.docx) 时代码格式混乱** 而开发的一键式文档转换工具。它结合了 Pandoc 强大的文档处理能力与深度调优的 Word 样式预设，使得导出的 Word 文档拥有媲美专业技术书籍的代码排版。

### Q2: 为什么我需要文匠？
**A:** 常规的文档转换工具（如默认的 Pandoc、在线转换网站或直接复制粘贴）由于缺乏对 Word 内部样式表的精准绑定，转换后的代码块通常会面临换行丢失、无等宽字体、无灰底边框等严重问题。文匠通过内置的专属格式模板解决了这一核心痛点。

### Q3: 文匠是免费的吗？

## 🚀 使用与操作问题

### Q4: 如何开始转换我的 Markdown 文档？
**A:** 
1. 下载文匠打包好的客户端 `wenjiang.exe`。
2. 双击打开运行，无需配置任何 Python 或 Pandoc 环境变量。
3. 点击“选择文件”导入您的 `.md` 文档。
4. 点击“开始转换”按钮，即可在同级目录下快速生成高保真排版的 `.docx` 文件。

### Q5: 转换后，Word 文档里的代码块为什么还是没有背景色和框线？
**A:** 请依次排查以下三项：
1. 确保您的 Markdown 文件中，代码块是用三个反引号（\`\`\`）包裹的。
2. 确保您在代码块开头标注了正确的编程语言类型（例如：\`\`\`python ）。
3. 检查反引号是否前后成对出现，且没有其他非标符号混入。

### Q6: 文匠目前支持哪些编程语言的代码高亮？
**A:** 支持 26+ 种主流及常用的开发与配置文件语言，包括但不限于：
- Python, JavaScript, TypeScript, Java, Go, Rust, C/C++, C#, Swift, Kotlin
- HTML, CSS, SQL, Shell/Bash, PowerShell
- JSON, YAML, XML, TOML, Markdown, LaTeX 等。

### Q7: 在 Markdown 中的行内代码（Inline Code）在 Word 中会如何显示？
**A:** 行内代码（即用单个反引号包裹的短代码，例如 \`code\`）在转换后将呈现为经典的**玫红色等宽字体，并带有淡灰色背景**。

### Q8: 文匠支持批量文档转换吗？
**A:** 支持。高级用户可以使用文匠的命令行版本，或通过编写简单的脚本进行批量处理。详情请参阅 [高级用法部分](https://github.com/xiaoyu12657/wenjiang-markdown#%E9%AB%98%E7%BA%A7%E7%94%A8%E6%B3%95)。

## 🛠️ 技术与自定义问题

### Q9: 文匠和 Pandoc 的关系是什么？
**A:** 文匠的核心引擎依赖于 `Pandoc` 来处理 Markdown 抽象语法树（AST）的分词和转换，但文匠的核心价值在于通过 Python 接口封装、预装绿色环境、以及预设精心定制的 `reference-doc` 模板样式。

### Q10: 我可以自己定制导出的代码块背景颜色或字体吗？
**A:** 可以。文匠的 Word 模板存放在 `templates/office_basic.docx`，您可以直接用 MS Word 打开该模板，并在“样式”窗格中修改 `SourceCode` (代码块) 和 `Verbatim Char` (行内代码) 的具体格式（如字体名称、大小、段落背景颜色、框线等）并保存。下一次转换时，文匠将自动渲染您定制的样式。

### Q11: 转换技术原理是怎样的？
**A:** 
```
Markdown 源文档 ────> Pandoc 解析 ────> 匹配 Word 优化模板 ────> 完美版 Word 文档
```

### Q12: 生成的 Word 文档支持什么版本的 MS Office？
**A:** 支持 **Microsoft Word 2010 及以上版本**，同时兼容 WPS Office。

### Q13: 可以使用文匠进行 PDF 或 HTML 的格式转换吗？
**A:** 目前文匠的主程序仅专注优化 **Markdown 到 Word (.docx)** 的转换。对于 PDF 转换，我们建议先转换至 Word 确认排版无误后，直接在 Word 中“另存为” PDF 即可获得最精准的效果。

## 🔍 问题排查与故障解决

### Q14: 运行时客户端提示“缺少 Pandoc 组件”？
**A:** 文匠的安装包中已经内置了绿色免安装的 Pandoc 运行环境。如果运行报错，请确保您下载的是完整包，且没有安全软件误将安装目录下的核心动态库/子程序拦截或删除。

### Q15: 大文档转换很慢是什么原因？
**A:** 如果转换超过数分钟，可能原因包括：
- Markdown 文档中包含大量的大尺寸本地图片或网络图片（文匠需要拉取并将其嵌入 DOCX 文件）。
- 文件大小超出了限制（建议单个文档大小控制在 10MB 以内）。

### Q16: 转换后图片无法显示或显示为红叉？
**A:** 请检查 Markdown 中的图片引用路径是否正确。我们强烈建议使用相对路径（如 `./images/pic.png`）或合法的互联网绝对 URL 链接。

### Q17: 转换后中文出现乱码怎么解决？
**A:** 请在保存您的 Markdown 文件时，确保将文件编码格式设置为 **UTF-8**。使用 GBK 或 ANSI 编码的文件可能会导致转换后中文呈现为乱码。
