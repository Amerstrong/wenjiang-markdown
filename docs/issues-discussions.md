```markdown
## 📖 痛点与背景

在日常的软件工程开发、学术论文撰写以及产品技术方案交付中，**Markdown** 凭借其极致的轻量性与纯文本可读性，已经成为了程序员和技术工作者的首选写作语言。然而，商业世界的文档流转和归档通常只承认 **Word (.docx)** 格式。

当我们尝试将写满核心代码的 Markdown 文件转换为 Word 时，一场排版灾难便开始了：
1. **缩进瞬间坍塌**：Python 或 YAML 这种强缩进的代码块，所有换行和缩进可能会在一瞬间丢失，所有代码被强行挤在单行段落中。
2. **样式寡淡无奇**：默认转换出来的代码既没有深浅背景色的反差对比，也丢失了语法高亮，通篇黑白，难以阅读。
3. **字体非等宽**：Word 默认会将普通字体（如宋体、微软雅黑）应用在代码上，导致缩进对齐参差不齐。

本文将深入探究该排版问题的底层机理，并提供包括**手动深度配置**与**工具一键解决**在内的完整技术方案。

---

## 🔍 底层成因：Pandoc 的抽象树解析与 Word 样式表

要彻底解决此问题，我们必须理解转换工具（以最强大的文档转换器 Pandoc 为例）的工作原理。

Pandoc 的核心是一个多格式编译器，其转换流程如下：
1. **解析**：读取源 Markdown 文本，构建出抽象语法树 (AST - Abstract Syntax Tree)。
2. **样式查找**：在目标 `.docx` 的二进制容器中，检索名为 `SourceCode` 的段落样式表，以及针对行内代码的字符样式（通常为 `Verbatim Char`）。
3. **应用与渲染**：将 AST 中的代码节点封装，应用检测到的样式，最终打包输出。

**为什么默认转换出来的代码很丑？**
因为 Microsoft Word 默认的通用样式表中，要么**根本不存在** `SourceCode` 段落样式，要么该样式**默认未进行任何底纹、边框和字体绑定**。Pandoc 找不到这些定义，就会降级采用 Word 的“正文 (Normal)”样式进行替代渲染，进而导致格式全部丢失。

---

## 💡 终极解决方案

### 方案一：硬核极客法——手动创建 reference.docx 样式库

如果您是技术控，想要完全自主掌控转换模板，可以采用此方法定制属于您自己的样式：

#### 第一步：提取默认模板
打开命令行，执行以下 Pandoc 原生指令以提取出一份包含全量样式表的空 DOCX 文件：
```bash
pandoc --print-default-data-file reference.docx > my_reference.docx
```

#### 第二步：在 Word 中修改 `SourceCode` 段落样式
1. 使用 Microsoft Word 打开 `my_reference.docx`。
2. 在工具栏中打开**样式 pane**，找到名为 **SourceCode** 的样式（若找不到，需在设置中选择“显示所有样式”）。
3. 右键点击并选择“修改”：
   - **字体**：将西方字符设置为 `Consolas`，字体大小调整为 `9.5 pt`，以保证代码字符完全等宽对齐。
   - **格式 - 段落**：设置“左缩进”为 `0.35 英寸`，设置行距为 `1.2 倍行距`。
   - **格式 - 边框**：在“底纹”选项卡中选择浅灰色填充（推荐十六进制代码 `#F5F5F5`）；在“边框”选项卡中添加单线实线细边框，颜色设为灰色（推荐 `#CCCCCC`）。
4. 保存此 `my_reference.docx` 文件。

#### 第三步：应用样式进行转换
在终端输入以下指令，指定您刚才调整过的参考文档：
```bash
pandoc input.md -o output.docx --reference-doc=my_reference.docx --highlight-style=tango
```

## 🚀 方案二：降维打击——使用文匠 (Wenjiang) 一键转换

手动配置样式库过程繁琐且在不同版本的 Office 软件间可能会出现格式回弹。针对非技术人员或不愿折腾的开发者，**文匠** 提供了封装好的解决方案：

1. **预设调优模板**：内置深度修改的 `office_basic.docx`，对 `SourceCode` 进行了高标准的细节微调（Consolas 9.5pt + #F5F5F5灰底 + 细边框包裹 + #C7254E行内高亮）。
2. **环境全内置**：无需配置 Python 环境，无需配置 Pandoc 环境变量，绿色单文件解压即用。
3. **命令行与 GUI 双持**：既适合习惯可视化拖拉拽的非技术人员，也适合通过 CLI 脚本进行批量集成的极客。

```bash
# 1. 下载文匠 wenjiang.exe 并放入项目
# 2. 运行并一键转换
wenjiang document.md document.docx
```
